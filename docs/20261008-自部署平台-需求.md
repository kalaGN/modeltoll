# 自部署模型管理平台需求

确认依据：2026-10-08 用户要求“按照优先级开发”。当前平台已有账号、Key、个人统计、管理员总览和品牌配置。

## 交付顺序

1. P0-1 模型服务接入：管理员设置一个 OpenAI 兼容上游的 Base URL、模型名、超时，测试连接；用户用平台 Key 调用非流式 Chat Completions。
2. P0-2 部署与管理员初始化：可复现安装、环境模板、数据库迁移、明确指定首个管理员。
3. P0-3 管理员用户和 Key 管理：用户停用、Key 撤销、审计，保留个人数据隔离。
4. P0-4 RPM、并发和 Token 配额，先定义作用域及准确的扣减/预留规则。
5. P0-5 可靠计量：超时、断连、重复请求、记账失败及恢复流程。

本轮先交付 P0-1 的完整垂直切片，其余保持待实施，不称为已完成。

## P0-1 验收

- 保留现有 Laya `/v1/predict` 和客服接口；默认启动行为不变。
- 新增 `/v1/models` 和 `/v1/chat/completions`，仅平台 Bearer Key 可访问。
- 只支持文字消息、单个固定模型、非流式；未支持字段明确拒绝，不宣称全部 OpenAI API 兼容。
- 管理员读取、保存、连接测试要求角色；写操作要求 CSRF。普通用户不能指定上游 URL 或凭据。
- 上游 Key 仅使用环境变量 `UPSTREAM_API_KEY`，不落数据库、不返回、不记录日志。
- 价格仍为 1 元 / 百万输入 Token。输出 Token 记录但不收费；仅成功且用量有效的调用计费。
- 配置切换不影响已接受请求的模型和价格快照。上游超时/故障映射为 504/502，无自动重试。
- 用量必须是非负整数；缺失/畸形返回失败，不伪造 0 用量或成功。
- 可通过 `LAYA_RUNTIME=external` 跳过本地 Laya 权重加载；此时原 Laya 接口明确返回 503。

## 非目标

本轮不做流式、图片、工具调用、Responses API、多模型路由、支付、输出定价、自动模型下载或公网暴露。

## P0-4B 候选：月度输入 Token 软阈值（2026-10-10，待确认）

事实：平台只有响应后的准确输入Token用量；外部上游没有已集成的预计算接口。本地及外部模型的输入Token口径由各自运行时提供。现有账务只为成功且用量有效的调用生成 `usage_charges.billable_input_tokens`。

提案假设（尚未确认）：先提供用户共享的UTC自然月成功计费输入Token软阈值；默认关闭，使用统一运维变量，不新增用户额度编辑页面。不改变单价、计费资格或输出Token不收费规则。

- 同用户所有Key及三条推理接口共享；管理员用户不豁免，其他用户独立。
- 达到或超过阈值后，拒绝后续新请求；已接收/排队/运行请求仍可完成。单次调用和并发请求可能超过阈值，不能承诺最终用量绝不超额。
- 只统计当月完成入账的输入Token。失败、未知用量及未结算请求不计入此数；因此它不代表真实上游消耗或严格成本上限。
- 跨月按费用入账时间归属新月份，不按请求开始时间；UTC不是北京时间，月初本地08:00切换。
- 运维开关不改历史账务；月度统计应读取既有费用事实，不回填或重写旧数据。

待确认：是否接受软阈值，以及UTC自然月、成功入账输入Token、全用户统一运维额度的口径。若必须硬上限，先选择可信Tokenizer/上游预计算及逐请求预留规则，此提案不实施。
