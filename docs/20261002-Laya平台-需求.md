# Laya API Key 管理与计费平台需求

创建日期：2026-10-02（Asia/Shanghai）。状态：已确认目标与定价，部分业务细则待确认。
本文定义目标行为，不代表功能已经实现；本次仅落地需求，不修改代码或数据库。

## 1. 背景与现状

项目目标是在 Laya 模型服务上提供邮箱账号、API Key 管理、接口鉴权、调用统计和费用统计。
用户已明确：使用邮箱和密码登录；价格为人民币 1 元 / 1,000,000 Token。
此定价替代此前提出的按调用次数收费建议。

当前代码事实：

- `api.py` 提供 `/health`、`/v1/customer-service/analyze`、`/v1/predict`。
- 尚未实现用户、登录、API Key、用量账单、持久化或管理界面。
- multilingual 模型启动时加载，两个推理接口共享实例和线程锁。
- `/v1/predict` 返回 Laya 原生 usage；客服 `analyse` 当前没有透出 usage。
- 已安装 Laya 0.3.23 返回 input_tokens，output_tokens 为 0。源码中的 input_tokens
  是模型处理序列的用量，不应解释成仅客户 message 的字符数或 Token 数。

## 2. 目标与范围

用户使用邮箱和密码登录，申请 API Key，通过 Key 调用 Laya 模型接口，
并查看自己各 Key 的调用记录、Token 用量和人民币费用。

第一阶段需求包含：账号登录、Key 申请与管理、推理鉴权、用量记录、调用统计、费用统计。
注册与邮箱验证、密码重置、充值/支付、预付余额及欠费拦截是否进入第一阶段待确认。
未确认功能不默认纳入实施验收。

本需求不包含聊天文本生成、模型训练、其他模型供应商或自动改变客服分流阈值。
数据库、邮件服务、会话机制、前端框架和部署方案由设计确定，不在需求中指定。

## 3. 账号与登录

### R01 邮箱和密码登录

- 邮箱作为登录标识；正确凭据获得登录状态，退出后该登录状态失效。
- 错误邮箱/密码以统一错误反馈，避免泄露账号是否存在。
- 密码以安全的单向密码哈希存储，不保存明文或可逆密文，不写入日志。
- 未登录用户不能申请 Key、查看用量或账单；用户只能访问自己名下数据。
- 登录必须具有暴力尝试防护；次数、时间窗口与会话有效期在设计前确认。
- 用户来源（自助注册/管理员创建）、邮箱验证与密码规则见待确认事项。

## 4. API Key 生命周期

### R02 申请 Key

- 登录用户能够申请绑定自己账号的 API Key，并得到调用示例。
- Key 具有不可预测的随机秘密，不以用户 ID 或邮箱生成可猜测秘密。
- 完整秘密仅在创建成功时展示一次，后续列表只展示脱敏标识。
- 持久化保存安全校验值而非完整明文 Key；日志和账单不得包含秘密。

### R03 查看与撤销 Key

- 用户可查看自己 Key 的标识、创建时间、状态和最近使用时间。
- 用户可撤销自己的 Key；撤销后新请求不得使用该 Key 成功推理。
- 撤销不删除历史调用和费用记录，不改变历史归属。
- 多 Key、命名、到期、轮换和配额是否提供以及数量上限待确认。

## 5. 推理接口鉴权

### R04 使用 Key 调用

- 客服和原生预测接口均需验证 API Key，成功请求归属到用户和 Key。
- 缺失、非法、撤销及不属于有效账号的 Key 被拒绝，不执行模型推理。
- API Key 的 Header 格式和具体拒绝状态码在设计文档确定。
- 原有问题类型、模型和客服业务输出保持现有语义；新增鉴权会改变公开调用契约，
  必须提供更新后的文档、示例及本机旧调用方式的迁移说明。
- health 与接口文档是否公开、登录会话是否可以直接调用推理接口待确认。

## 6. 用量与计费

### R05 Token 口径

- 定价已确认：人民币 1 元 / 1,000,000 Token。
- 当前使用输入 Token 作为计费量，采用服务端 Laya 返回的 usage.input_tokens，
  不接受客户端自行上报的计费用量；output_tokens 当前为 0。
- 记录模型、用量口径/价格版本和生效时间，未来变化不重算历史账单。
- 原生请求中的 state、问题 instructions 与 criteria 会参与模型输入；多个问题可能
  使共享 state 被计入多个处理序列。不得承诺仅按客户文本 Token 收费。
- 客服接口内部使用多个预设问题，设计时必须保留原生 usage 来计量，不能按字符估算。
- 长输入截断时采用模型实际报告的 input_tokens，同时保留截断标记供解释。
- 失败、超时、断连、重试、重复请求的计费资格仍待确认，未确定前不得隐藏采用策略。

### R06 费用计算与展示

费用（元）= 计费 input_tokens / 1,000,000。

| 计费 Token | 理论费用（元） |
| --- | --- |
| 1 | 0.000001 |
| 1,000 | 0.001 |
| 1,000,000 | 1 |

- 账务计算使用精确十进制或整数最小单位，禁止二进制浮点累积费用。
- 单次小额费用不得先舍入至分再累加，避免低于 0.01 元的调用丢失费用。
- 页面展示位数与账单结算舍入方式待确认；展示舍入不得修改账务原值。
- 请求必须有唯一记录标识，单条调用记录与费用不得因并发写入而重复记账。
- 推理成功而用量记录失败时的返回/补偿方案、数据保留及历史价格变更由设计明确。

## 7. 调用与费用统计

### R07 调用明细

- 用户可查看自己的调用记录，至少包含请求标识、Key 脱敏标识、接口、模型、
  请求时间、结果状态、耗时、输入/输出/计费 Token、费用和价格版本。
- 可按时间范围、Key 和接口查询，并提供有上限的分页。
- 记录失败调用以便统计，但账务是否产生费用遵循待确认的计费资格。
- 鉴权失败时不把无法验证归属的请求写入其他用户账单，可计入服务安全日志。
- 默认统计记录不保存客户原文、密码或完整 Key。

### R08 汇总统计

- 按用户、Key、时间范围展示调用总量、成功/失败量、Token 总量和费用总额。
- 汇总可追溯到同一范围的明细，不能把未计费调用量误作计费 Token。
- 撤销 Key 后，其历史用量仍计入所属用户汇总。
- 分页大小、统计时区、时间边界、更新延迟和数据保留期限待确认。
- 提供查看这些结果的后端查询能力；是否同时交付网页管理控制台待确认。

## 8. 验收标准

| 编号 | 可测试验收 |
| --- | --- |
| A01 | 正确邮箱密码登录成功；错误凭据返回统一失败；退出后受保护管理请求失败 |
| A02 | 未登录不能管理 Key；用户 A 无法读取或撤销用户 B 的 Key、调用或费用 |
| A03 | 创建 Key 显示一次完整秘密，列表仅脱敏；数据库和日志无明文密码或 Key |
| A04 | 有效 Key 可调用两个推理接口；缺失、非法和撤销 Key 不进入模型推理 |
| A05 | 成功调用的用户/Key/请求标识、原生 usage 与明细匹配；客户端伪造 usage 不生效 |
| A06 | 计费 1 / 1000 / 1000000 Token 分别得到 0.000001 / 0.001 / 1 元原值 |
| A07 | 1000 次各 1 Token 调用累计 0.001 元，未发生逐次按分舍入丢失 |
| A08 | 相同统计范围的汇总与明细可对账；撤销 Key 不删除或重算历史费用 |
| A09 | 并发调用有独立记录且同一记录不重复计费；重试语义按确认策略验收 |
| A10 | 失败/超时/断连场景依据已确认计费资格产生正确记录与费用 |
| A11 | 原有分类、评分、真假概率语义及客服阈值不发生无需求变更 |
| A12 | 鉴权迁移说明和新的调用示例与实际实现一致 |

A01–A04 依赖登录会话、账号来源及鉴权契约的设计；A09–A10 的策略未确认前不算完成。
不得用假 Router 测试通过来证明真实 Laya 的用量口径或准确率。
