# 管理员后台设计

状态：用户已确认平台总览并追加平台配置；已按“开发吧”实施并验证。

## 数据与认证

新增 0005_user_admin.sql 与回滚，通过 information_schema 判断后添加 is_admin BOOLEAN NOT NULL DEFAULT FALSE，附 0/1 CHECK。保持旧迁移不变，纳入 models.MIGRATIONS。
accounts.User 增加 is_admin: bool = False，public 扩充该字段；注册写入默认 false；fetch/current_user 从 users 读取角色并转换 bool。管理员身份由当前数据库行确定，不保存在客户端或长期会话角色快照中。
新增 require_admin 依赖，复用 require_user，普通用户返回平铺 {code:admin_required,message:需要管理员权限}、403。
登录前端依据响应角色跳转；根路由依据服务端角色跳转。/admin 页面服务端检查 require_admin。管理员个人页面增加管理入口，普通账号不显示。

## 平台只读接口提案

- GET /v1/admin/overview?from=&to=：会话＋管理员；from/to 复用现有 UTC 半开时间范围校验。返回 {code,range,totals{users,active_keys,calls,amount_yuan,currency},series[{date,calls,amount_yuan}]}；账号数与密钥数是当前存量，调用和费用按时间窗口（最多 366 天）。
- 聚合先分别按用户归并密钥、调用、费用再连接账号，避免一对多 JOIN 放大金额。密钥排除 deleted_at 非空；历史调用和费用不因密钥软删除丢失。仅返回脱敏管理信息，不返回密码哈希、会话或完整密钥。
- 不改变现有个人统计接口的数据范围。

## 页面布局

沿用 console-shell 与现有响应式侧栏。左侧品牌及“平台总览”和“平台配置”导航，底部保留退出；平台总览和平台配置页顶部右侧显示“切换到个人控制台”按钮，跳转 /keys。
主区域顶部为“平台管理”及中文说明，右侧时间窗口（默认最近 7 个 UTC 日）。取消装饰英文小字与顶部面包屑。
四项指标以大数字、细分隔线排列：账号总数、可用密钥、窗口调用量、窗口费用；金额注明人民币及窗口。
下方两张白色趋势卡片：按 UTC 日的调用量柱状图与费用折线图，提供日期与数值标签。费用卡注明当前计费口径；不展示用户邮箱或明细。
无数据展示“所选时间暂无调用”；接口失败显示错误和重试；窄屏指标两列、侧栏转顶部导航、趋势卡片单列。
视觉预览中的指标均为示意，实施使用真实接口。

## 兼容、风险与回滚

新增 Pillow 图片验证依赖（>=11,<13，本机 12.3.0），不变更模型、推理锁和计费策略。增加认证 JSON 字段为本次明确契约扩展。管理员只读权限能查看平台聚合用量，应由用户明确选择首个管理员，不能自动把首个注册账号升权。
先回滚后台、认证及跳转代码，再移除字段和约束；回滚导致管理员入口不可用，普通登录、个人数据和账务保留。DDL 不自动回滚。

## 验证

标准库 unittest 覆盖角色映射、注册不能升权、普通/未登录管理员接口拒绝、管理员成功、降权当前会话失效、登录跳转及原个人隔离。
隔离 MySQL 事务验证迁移幂等与跨用户聚合不重复、软删除历史保留；浏览器验证两种角色的登录落点、无数据与错误、时间窗口及手机布局。已有删除套件回归。

## 平台配置页面与持久化

新增 /admin/settings，复用 require_admin 页面权限。布局沿用现有配色、中文标题和表单卡片；主区域标题“平台配置”，下方左侧品牌表单、右侧登录/侧栏品牌预览，窄屏上下排列。字段依次是平台名称、Logo（当前缩略图、上传、更换、恢复默认）、平台简介；底部“保存配置”。不增加装饰英文小字或面包屑。

新增 0006_platform_settings.sql 及回滚：platform_settings 单行（id=1），保存 name、description、logo_blob、logo_mime、updated_at。Logo 体积受限，存于 MySQL 避免新增文件目录与文件生命周期设施。默认 Logo 以 NULL 表示。DDL 为唯一结构来源；回滚删除配置会丢失品牌定制，先回滚调用代码，不自动执行。

- GET /v1/platform/branding：公开返回 {code,branding{name,description,logo_url}}，不暴露其它平台配置。
- GET /v1/platform/logo：只返回已验证的图片内容，固定 Content-Type 与 nosniff；默认 Logo 为前端现有图形。logo_url 携带 updated_at 版本避免替换后缓存旧图。
- PUT /v1/admin/settings：管理员会话＋CSRF，JSON {name,description,logo_data_url}；logo_data_url 为 null 保留当前 Logo、空字符串恢复默认，data URL 仅接受上述图片类型。整体请求限制约 3 MB，解码后限制 2 MB；检查文件格式、图片尺寸和有效性后才提交同一事务。保存返回规范化 branding。
- 实施检查发现 Pillow 未安装，已在 commentary 说明用途、更新 requirements-api.txt 并安装，uv pip check 通过。新增依赖仅用于上传图片验证；回滚代码后可移除该声明，不影响模型配置。拒绝格式伪装、超大尺寸或损坏图像，不输出上传内容到日志。
- 平台名称和简介用 textContent 展示，禁止 innerHTML。品牌读取失败使用现有 Laya 默认值，后台配置读写失败显式报错。
- 已保存配置跨进程重启保留；未保存预览仅在本页面生效，保存失败不能影响其它页面品牌。

验证覆盖管理员/普通/匿名权限、CSRF、文字边界、格式伪装/损坏/超限图片、恢复默认、保存原子性和公开字段范围；浏览器验证上传预览、保存失败、刷新后的跨页面品牌一致性及手机布局。

实施差异：总览使用费用 call_id 唯一约束保证 LEFT JOIN 不放大调用数，以日汇总计算窗口总计；可用密钥排除停用账号。为屏幕阅读器提供每日数值表。Logo 验证后最多缩放为 512px 并统一 PNG；保存接口先限制流大小再解析 JSON，OpenAPI 明确 JSON 契约。
