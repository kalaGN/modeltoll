## 1. 目标与已核实问题

保留 FastAPI 模块化单体、原生 SQL、单 worker 和单模型锁。分层服务于职责和测试，
不以增加目录数量为目标。

当前源码事实：

- main.py 154 行，混合 lifespan、路由注册、异常处理、页面导航和静态文件缓存策略。
- db/models.py 没有 ORM 实体，而是执行 migrations/ 下的 SQL。
- api/v1/gateway.py 导入 api/v1/inference.py 的多个私有 HTTP 协调函数。
- services/gateway.py 同时包含连接配置持久化、价格初始化和上游 HTTP 传输。
- services/platform.py 同时管理品牌图片和管理员聚合查询。
- SettingsRequest 定义在 admin 路由中，而非 schemas；schemas/auth.py 又使用服务层校验，存在契约与业务耦合。
- 服务文件约 21–358 行，不存在必须全面拆成复杂 DDD 分层的证据。

## 2. 分层与职责

| 层/位置 | 负责 | 不负责 |
| --- | --- | --- |
| 组装 main.py、lifespan.py | 创建 app、注册模块、模型和数据库启动检查 | 页面业务、推理记账规则 |
| 接口 api/ | HTTP 参数、认证/CSRF 依赖、响应和错误映射 | 拼业务 SQL、决定收费策略 |
| 契约 schemas/ | Pydantic 输入与输出契约、字段约束 | 查询数据库、载入模型、依赖路由 |
| 业务 services/ | 账号/Key、配置、调用状态、计费、恢复、统计；掌握事务边界 | 返回 FastAPI Response、执行第三方 HTTP 传输细节 |
| 数据设施 db/ | MySQL 连接、游标、事务上下文、迁移执行 | 认证/计费业务决定、隐式提交业务事务 |
| 模型设施 integrations/ | 本地 Laya 生命周期和锁、固定上游 HTTP 访问 | 管理用户、写费用、解释业务政策 |
| 公共配置 core/ | 环境配置、安全基础函数和纯校验 | HTTP 导航、页面状态、业务编排 |

schemas 是接口契约，不是数据库实体；现阶段不引入 ORM models 目录。
后端不设 web/，页面路由和静态托管全部归 frontend，HTML 不复制到后端或 API 镜像。

## 4. 依赖和事务红线

1. main 负责组装，API 负责 HTTP 适配；服务不得反向导入 API/main，后端不承载业务页面。
2. 路由不互相导入私有函数；推理共享 HTTP 协调集中在 api/http/inference.py。
3. schemas 不依赖 services；共用的纯邮箱等校验提取到 core/validation.py，保留原阈值和错误结果。
4. 业务服务调用 db 或模型适配器。现有 services 对 schemas 的参数类型依赖逐项记录，不能在本轮顺便重写所有 DTO/函数签名。
5. integrations 不导入 services、路由或 main。传输适配器不偷偷重试、不改超时、URL、凭据或用量验证策略。
6. 含 SQL 的现有服务可以保留原生 SQL。没有重复查询或独立替换需求时，不强制增加 Repository/DAO 包装。
7. 事务由业务操作掌握，数据设施不得自行提交子操作。记账、终态、审计和幂等的原子性不因搬文件变化。
8. 恢复与正常结算必须复用同一业务函数；不能把它们拆成两套结算实现。
9. 本地模型实例和锁只保留一份，迁移后不允许旧/新模块各加载一份。

示例导入风格（目标路径，不代表已实现）：

```python
from app.services.inference import lifecycle, recovery
from app.integrations import laya_runtime
from app.db import connection
```

不新增统一响应包裹、不重命名 API 字段、不改状态码或 HTTP 响应头。

## 5. 分批实施计划

| 顺序 | 切片 | 验收 |
| --- | --- | --- |
| 0 | 保存默认回归、OpenAPI 和页面路由基线 | 旧有 178 个用例逐项可映射；记录原 operation_id/参数/错误结构 |
| 1 | db 模块语义命名，每次一个文件 | 同步所有导入与 mock 目标，不执行迁移、不访问真实数据库 |
| 2 | main 拆出 lifespan、API 汇总和错误 | app.main:app 保持；页面逻辑迁到前端，不新增 web；无导入时副作用 |
| 3 | API 共享 HTTP 协调及有界 JSON Route | gateway 不再导入 inference 路由私有函数；三推理入口计费/限流/去重行为一致 |
| 4 | 管理员与公开 API 按访问职责拆开 | URL、权限、CSRF、operation_id、请求体限制不变；不改为仅依靠目录授权 |
| 5 | schemas 中集中 SettingsRequest、提取共用纯校验 | 422 校验、长度/类型/邮箱边界不变；schemas 不再反向依赖服务 |
| 6 | 管理业务及推理业务分包，每次一个业务模块 | 逐模块同步服务、路由、CLI、测试和文档；锁与事务边界不变 |
| 7 | 模型适配器分离 | external 模式仍不导入 Laya/Torch；离线本地模式不新增下载；无自动重试 |
| 8 | 全量回归与文档同步 | 原契约及测试保持，新增结构边界检查；未验证项单列 |

每次移动后同步引用并执行相关回归，不一次改完所有层再排错。
涉及许多引用的机械重写使用可审查补丁；不重写尚未理解的推理或结算函数。


OpenAPI 应与迁移前完整 JSON 比较，不只比较路径数量，避免移动函数后 operation_id 改变。
Python AST 与导入边界检查覆盖循环依赖；import app.main 不得因结构改变就连接数据库或加载模型。
补充 TestClient 的页面/静态文件、公共品牌/管理员、请求体限制和推理错误路径验证。
真正的启动和模型测试单独记录，不能用模拟对象证明 MPS 推理或 MySQL 并发正确。

- 当前用户正在测试本机服务，本规划不修改代码、不停止或重启服务。
- 后续实施默认用独立测试环境；启动器、容器和运维入口保持。
- 不修改数据库 DDL、迁移行为、.env、用户/Key/费用数据，不因重构自动下载模型。
- 原有前端及测试目录改动尚未提交，必须保留，不能用 Git reset/checkout 清理工作区。
- 回滚按上述切片恢复代码与导入；不回滚业务数据，不操作迁移回滚 SQL。
- 不自动提交、推送、部署。Lint/类型检查仍未配置，不将其列为通过。
