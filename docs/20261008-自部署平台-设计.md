# 自部署平台设计

## P0-1

- `services/gateway.py` 管理单个连接配置和受限 HTTP 转发；`schemas/gateway.py` 定义严格输入。
- `api/v1/gateway.py` 提供管理员配置、连接测试、平台模型列表和 Chat Completions。
- `0007_model_gateway.sql` 新建单行配置表。配置保存和首次模型价格建立在一个短事务中；价格历史不修改。
- 价格版本使用随机标识；现有模型若已定价，沿用已生效价格，不覆盖历史。
- 每次接受请求读取配置快照，共享当前单进程推理锁；等待锁最长 30 秒，拿到锁后重验 Key。
- HTTPX 禁止重定向、禁用环境代理（避免凭据意外转发）、限制上游 JSON 响应为 2 MB；连接超时最多 5 秒，读超时由管理员配置 1–300 秒。
- HTTPX 超时是每次网络操作超时，不是整个生成的绝对截止时间；不得宣称总耗时上限。
- URL 仅管理员控制，允许 http(s) 内网服务（这是用途），拒绝用户名/密码、query、fragment。Base URL 必须带 `/v1`；无自动跳转。
- 管理员配置被视为可信运维权限，不能用普通用户输入改变出站目标；有上游凭据时禁止明文连接到非 loopback 地址。
- 返回上游成功 JSON 但用平台 X-Request-Id 标识；账务只认上游 prompt_tokens/completion_tokens，不认客户端 usage。
- 客户原文只在内存转发，不进入调用表。上游错误正文不向客户透传。
- `LAYA_RUNTIME=local` 默认保持本地模型；external 模式延迟导入 Laya，仅提供远程聊天。

## 兼容与回滚

现有接口和表不删改。新依赖 `httpx>=0.28,<0.29`（当前虚拟环境已安装），新增迁移可重复执行。
回滚先停止服务并还原代码，再执行 0007 回滚；保留 pricing_rules/账务历史，不删除新模型价格。
外部模式不安装、启动或修改上游服务；需要运维先部署模型。默认仍 loopback、单 worker。

unittest MockTransport 注入上游成功、超时、错误、畸形用量和超大响应；TestClient 验证角色、CSRF、Bearer、锁超时及计量顺序。
前端构建和实际浏览器验证分别记录；模拟上游不代表真实模型准确性。

## P0-3 管理员用户与 Key 管理（2026-10-08 用户确认实现）

目标：管理员能够检索账号、停用/启用普通用户、查看并撤销用户 Key，且每次实际变更可追溯。保留调用和费用历史。不包含角色授予、密码重置、物理删除、充值或价格修改；不新增依赖。

安全边界：仅管理员 Session 可访问，写入继续要求 CSRF。本功能只修改普通用户状态，管理员账号（包括自己）不允许变更状态，亦不隐式激活停用管理员。停用普通用户会在同一事务撤销其现有登录会话；重新启用后需要重新登录，尚未撤销的 Key 恢复可用。已开始的推理不强制取消；排队请求沿用现有二次鉴权。

### 接口契约

| 接口 | 输入 | 输出与边界 |
| --- | --- | --- |
| `GET /v1/admin/users` | `q` 邮箱子串，`status` active/disabled，`page`，`limit` | 用户分页；邮箱搜索按字面处理 `%` / `_` |
| `PATCH /v1/admin/users/{user_id}/status` | `{status,reason}` | `{code,user,changed}`；管理员保护 409 `protected_admin`，不存在 404 `user_not_found` |
| `GET /v1/admin/users/{user_id}/api-keys` | `page`，`limit` | 含已撤销/软删除 Key；仅脱敏 display，无明文或哈希 |
| `POST /v1/admin/api-keys/{key_id}/revoke` | `{reason}` | `{code,api_key,changed}`；不存在 404 `api_key_not_found` |
| `GET /v1/admin/audit-events` | `page`，`limit` | 审计分页，无密钥、密码或客户原文 |

分页统一 `{code,items,page,limit,total,has_more}`；page 1–10000，limit 1–100（默认 20），q 最多 254 字符。路径 ID 使用 UUID。reason 去除首尾空白后 1–200 字符，拒绝额外请求字段。未登录 401，普通用户 403；相同状态、重复撤销或已软删除 Key 为无变更，不重复写审计。

用户项：`id,email,status,is_admin,created_at,last_login_at`。
Key 项：`id,name,display,status,created_at,last_used_at,revoked_at,deleted_at`，status 为 active/revoked/deleted。
审计项：`id,actor_id,actor_email,target_user_id,target_email,target_key_id,action,previous_status,new_status,reason,created_at`；action 为 `user.status_changed` / `api_key.revoked`，时间沿用 UTC ISO 格式。

### 存储与并发

新增 `0008_admin_audit.sql` 与对应回滚，创建 `admin_audit_events`：UUID 主键、操作者/目标用户外键、可空目标 Key 联合外键 `(target_key_id,target_user_id)`、动作、前后状态、原因、UTC 时间及分页索引。审计不是抵抗数据库管理员篡改的日志。

事务内重新确认操作者为启用管理员并锁定目标；状态变更/会话撤销或 Key 撤销与审计插入必须共同提交，失败全部回滚。修复登录流程在事务外读取账号状态的竞态：发放 Session 前锁定并复核当前状态，先建立失败回归测试。保持既有登录响应契约。

## P0-4A 用户请求限流（2026-10-09 已确认并实现）

目标：控制合法用户通过多个Key大量提交请求导致的资源挤占。首先交付RPM和在途请求限制，不将事后Token统计宣传为调用前硬配额。P0-4 Token配额仍为待实现，计费价格和既有成功响应不变。

### 规则与配置

- 作用域为服务端鉴权得到的user_id，同一用户全部Key和三条推理接口共享：`/v1/predict`、`/v1/customer-service/analyze`、`/v1/chat/completions`。不限制模型列表、网页、登录或统计接口；登录已有独立限速保持不变。
- 运维环境变量 `LAYA_USER_RPM` 与 `LAYA_USER_MAX_INFLIGHT` 默认0（关闭），有效范围分别0–100000、0–1024。启动时严格校验，不接受负数或非法字符串。建议显式配置60与1，但不自动更改本机环境或已有用户权限。
- RPM使用数据库UTC固定分钟窗口，不是任意滚动60秒；窗口边界可能相邻短时间内接受两倍额度，文档必须说明。每次通过限流准入的请求占一次RPM，不因后续上游失败退回；这是请求预算，不是费用或Token预算。非法请求、无效Key、本地模式不可用、未配置上游和并发/RPM拒绝不占RPM。
- 在途数包含排队、推理和结算期间的请求，不是同时运行的模型数。先取得用户在途名额，再原子检查并递增RPM；任意正常返回或异常均在finally释放名额。仍保持单进程、单worker和全局推理锁，绝不借此放开模型并行。
- 固定窗口RPM持久化到MySQL，重启不重置同一分钟计数；在途计数使用受线程锁保护的进程内状态，仅支持当前单worker约束。用户计数降为0时移除内存项，不无限累积。
- 配额超限HTTP429，平铺`{code,message}`，业务码分别`rate_limit_exceeded`与`concurrency_limit_exceeded`；RPM返回距离下一窗口的整数秒`Retry-After`，并发返回1秒（重试建议，不保证1秒后一定可用）。拒绝时不创建调用/费用记录。数据库计数失败必须拒绝准入HTTP503 `rate_limit_unavailable`，不能绕过限流进入模型。

### 实施与存储

迁移0009及回滚新增 `request_rate_windows`：user_id外键、UTC window_start、非负request_count，联合主键(user_id,window_start)，窗口时间索引。计数通过短事务和行锁原子判断/更新，不跨推理持有数据库事务。只存ID/窗口/次数，不存Key或客户原文。清理使用独立autocommit连接先删除超过24小时的窗口（每次最多1000行），释放范围/gap锁后才进入准入事务，避免并发首次写入的锁冲突；绝不清理调用和费用历史，清理失败拒绝准入。
服务放在 `backend/app/services/request_limits.py`；配置沿用core/config，迁移注册沿用db/models；两个路由模块复用同一准入上下文。先查运行模式与模型有效性，再准入，再创建调用并等待模型锁。配置由运维环境提供，本批不新增管理员额度页面或用户个性化限额，避免未经确认扩大配置契约。
项目沿用Python类型注解、snake_case、四空格缩进及现有HTTP错误映射；不添加Redis、队列或生产依赖。实际依赖版本以元数据为准。

### 验收与回滚

1. 单用户多Key、跨三条推理接口共享预算，其他用户独立；并发争用不能超过限额。
2. 默认关闭时旧接口行为保持；超限429和Retry-After正确，拒绝不调用模型/不记费用；计数数据库失败503；上游、调用记录或结算异常释放在途名额。
3. 固定窗口切换、同窗口重启计数保留、空闲内存回收、临时窗口清理和历史账务不变均可复现。

验证命令：`PYTHONPATH=backend .venv/bin/python -m unittest discover -s backend/tests`；`npm --prefix frontend run build`；`git diff --check`。新增标准库Unit/HTTP测试先失败再实现；真实MySQL用随机隔离Compose项目验证竞争和窗口计数，Mock结果与数据库结果分别报告。没有Lint/类型检查，不引入未配置门禁。
回滚：运维可设两个值为0并重启关闭限流，再恢复旧代码。计数表无账务事实，需停用新代码后人工执行0009回滚；不自动执行，不恢复/重写任何费用。不重启本机已有进程、不修改.env、不自动提交或推送。

### P0-5B 成功回执与恢复（2026-10-10 已确认）

在业务payload构造成功且服务端用量有效后、正式结算前，短事务持久化只含call_id、用量元数据、成功事实、时间的回执；不保存提示词、客服原文、模型回复或Key。新迁移0010及回滚为唯一DDL来源，调用/价格快照仍取原记录。后处理失败不能拥有可收费成功回执。即使回执保存失败也不返回伪成功；若结果尚未持久化，不能宣称崩溃后可恢复。
新运维CLI默认只读巡检，明确 `--apply` 才恢复有可信成功回执、无终态矛盾的调用；锁定调用并复用幂等结算，补费沿用原价格版本、只写一次。原HTTP可能曾500，恢复可能产生费用，必须用户确认这个政策。未知用量/旧running/矛盾费用只报告待人工核查，不凭年龄填0或判成功；不干扰活动推理、不自动调上游。重复恢复无新费用。请求ID失败头应可供关联巡检。

### P0-5C 请求去重（2026-10-10 已确认）

可选 `Idempotency-Key`，未携带保持每次独立调用；携带时按可信user_id及Key摘要原子占位，不落明文Key。请求指纹包含endpoint/model/规范化body的摘要，不保存正文；同Key不同请求409 `idempotency_conflict`，同请求重复409 `request_already_processed` 与原调用ID（不缓存回复，不冒充可回放200）。占位与accepted调用同事务，重复拒绝不再推理/计费，跨用户隔离；活动/未知结果也不能重复执行。记录不自动过期删除，防止晚到重试再次收费。额外表DDL与错误体均需确认；没有持久去重不宣传网络重试恰好执行一次。

确认记录：用户选择“采用，按回执显式恢复并支持去重”。实现上述补账、持久回执与409去重契约；Idempotency-Key为1–128个可见ASCII字符（不含空格），非法值422；摘要为SHA-256，指纹为经Pydantic校验的请求规范JSON加endpoint/model。鉴权、输入校验和RPM/在途准入仍先执行，准入拒绝可能先于409返回。恢复命令为`recover-calls`，默认只读、`--apply --call-id`显式恢复单调用；回执只在完整JSON响应可构造后保存。恢复只允许可信成功回执，费用沿用原价格，模型完成时间与duration从回执保存，不用CLI进程计时。回执只读巡检每页最多100项，--offset为0–1000000，不输出正文、Key或数据库错误详情。
