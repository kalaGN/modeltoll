# 前后端彻底分离设计

日期：2026-10-18。方案已获用户确认，实施状态见任务。

## 文件与链路

- backend/app/main.py 删除 FileResponse/StaticFiles/页面跳转，core/config.py 删除 FRONTEND_DIST。
- frontend/scripts/serve.mjs：仅本地开发，Node 标准库提供 dist 页面与固定 API 上游代理，无新增 npm 依赖。
- frontend/src/shared/auth/session.js：CSRF 初始化和角色导航；API 权限仍由服务端验证。
- frontend/src/pages/index.js 与 templetes/index.html：根路径根据 /v1/auth/me 导航。
- frontend/Dockerfile：Node 构建阶段 + Nginx 运行阶段，只包含 dist 与代理配置。
- frontend/nginx.conf：显式八个页面路径、/assets、/v1、/health 和 API 文档映射；未知路径 404。
- 根 Dockerfile：仅 Python API，不安装 Node、不构建/复制 frontend。
- Compose：frontend 对宿主 loopback 发布 APP_PORT（默认 8000）；app/db 不发布宿主端口；数据库卷名称不变。

本地浏览器 → :5173 静态服务 → /v1 同源代理 → :8000 API。
容器浏览器 → loopback APP_PORT → Nginx → app:8000 → MySQL。
分离的是代码、构建与运行，不要求浏览器跨域；不增加宽泛 CORS 或浏览器持有上游凭据。

## 认证与代理

首次页面显式 GET /v1/auth/csrf，只有成功获取 CSRF 后允许写操作；已有有效 Cookie 不反复刷新。
公共品牌失败不阻断登录。控制台初始化失败不继续页面业务请求；管理员导航检查 is_admin，不能替代 API require_admin。
401 跳登录，非管理员访问管理员页面跳个人控制台；静态页面不含用户、Key 或费用数据。
代理保留 Cookie/Set-Cookie、Authorization、CSRF、X-Request-Id 和错误体；不重试模型请求，不缓存 API，不改请求路径/查询。
代理覆盖不可信转发头，保持登录限速的来源地址；容器 API 不直接发布，只有受控前端可提供可信代理头。
现有 HTTP-only/loopback 的 Cookie secure=False 不扩展为公网部署；TLS/公网另行评估。

## 验证和回滚

先建立失败测试，确认后端旧页面 404、镜像不含 frontend、独立页面无 Cookie 时能初始化。
测试用真实前端服务器代理到合成 API，不再由 fixture 直接供应静态页面，从而覆盖分离边界。
覆盖静态路径遍历/未知路径、API 不可用、Cookie、401/403、深链、刷新、管理员操作和原交互。
原 API OpenAPI 完整比较不应变化；后端回归和前端 Node 测试均执行，浏览器单独验证。
Docker 未运行则只报告契约验证，不能称镜像构建/部署通过。
回滚同时恢复后端页面托管和原前端构建部署代码，不操作数据库或删除卷。

命令（从根目录）：

```bash
npm --prefix frontend run build
npm --prefix frontend run dev
zsh run-api
PYTHONPATH=backend .venv/bin/python -m unittest discover -s backend/tests
npm --prefix frontend test
```

服务端 Python 保持类型注解与四空格，前端 ES Modules 使用显式导入；不增加空层、框架或生产 Python 依赖。
