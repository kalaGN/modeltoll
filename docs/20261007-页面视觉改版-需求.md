# Laya 页面视觉改版

日期：2026-10-07。状态：用户已确认生成的 API Key 效果图，并授权按图改版四页。

## 目标与范围

用户要求参考 Awwwards 已获奖作品重新设计页面，已确认登录、API Key、调用统计、费用统计四页统一改版，先以 API Key 页作为视觉样板。
目标是增强品牌辨识度、排版质量和交互清晰度，并保持管理平台的操作效率。
参考获奖作品的设计方法，不复刻其素材，也不将本项目描述为已达到获奖标准。

## 当前事实

- 页面在 frontend/src，使用 Tailwind CSS，共用 app.js；构建到 frontend/dist，由后端同源提供。
- 当前管理页使用固定宽度侧栏、蓝白卡片和表格；移动端导航需要重新布局。
- 登录品牌区含静态演示统计，改版需明确标为示意或替换为非数据品牌图形。
- 工作区已有后端、文档、api-keys.html 与 app.js 的未提交修改，必须在当前文件基础上保留。
- 不新增框架、字体服务、动画库或业务接口；不修改数据库、计费、时区、鉴权及模型策略。

## 拟定视觉方案

概念：让调用、密钥与成本成为清晰可读的控制界面。

- 暖白底 #F5F4EF、墨色 #18211D、酸橙强调 #D5F16A；成功与危险操作保留语义色。
- 使用系统字体，标题大幅拉开层级；数值与密钥使用等宽字体及等宽数字。
- 桌面为深色窄侧栏与浅色主画布；移动端为顶部品牌、横向导航和纵向内容。
- API Key 页：页眉标题与主操作；三项统计；密钥表；独立深色接入示例区。
- 登录页：原创品牌构图与直接可用的表单；不以虚构数据冒充账号统计。
- 统计两页复用相同导航、筛选器、指标、图表及明细视觉规范。
- 动效仅用于入场和状态反馈，约 160–240ms；支持 prefers-reduced-motion。
- 本次以用户已确认的原创 API Key 效果图为实施依据；Awwwards 仅作为设计参考，不声称完成具体获奖作品的视觉对照或奖项评审。

## 编码与边界

保留现有 HTML id、data-page、链接、表单字段与脚本钩子；新样式采用具名类与 CSS 变量，例如：

```css
.console-panel {
  background: var(--surface);
  border: 1px solid var(--border);
}
```

业务数据保持由现有服务端提供；秘钥完整值只显示一次。仅在交互可访问性确有需要时最小修改 app.js。
不创建 docs 子目录，不自动提交，不覆盖用户改动。

## 验收标准

1. 四页共享一致的颜色、导航、标题、按钮与面板规范。
2. 1440px、768px、390px 视口无页面级横向溢出；表格与代码块允许独立横向滚动。
3. 登录/注册切换、密码显示、Key 创建与一次性展示、复制、撤销确认、筛选和分页保持可操作。
4. 空数据、加载、错误、禁用按钮状态清晰；键盘焦点可见，弹窗可用键盘操作。
5. 对比度以 WCAG AA 为目标；主操作触摸区域至少 44px，减少动画设置下无非必要动效。
6. 不引入假统计、无功能按钮或未实现的服务宣传。
7. 构建与差异检查通过；浏览器验收记录实际执行范围，视觉模拟数据不作为真实后端验证。

## 验证命令与实施顺序

构建：`cd frontend && npm run build`。
脚本语法：`node --check frontend/src/app.js`。
差异：`git diff --check`。
真实服务：先检查现有端口；必要时 `zsh run-api --port 8010`，不终止其他会话进程。
项目未配置自动化测试、Lint 与类型检查，不能宣称这些通过。

顺序：确认视觉方案 → 浏览器分析获奖参考 → API Key 样板与验证 → 其余三页统一 → 全页回归与文档同步。
