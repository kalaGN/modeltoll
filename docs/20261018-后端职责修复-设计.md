# 后端职责修复设计

依据：[需求](20261018-后端职责修复-需求.md)。用户“修复”确认前一轮审查建议。
本方案取代旧分层草案中尚未实施的全面拆包建议；保持小而真实的边界。

## 位置与依赖

- api/inference_support.py：从推理路由迁出共用 HTTP 协调，两个路由显式导入。
- schemas/platform.py：SettingsRequest，保留原类型名、限制和手动有界读取。
- core/validation.py：纯邮箱规则；core/time.py：已有共享 UTC 格式化。
- integrations/openai_client.py：凭据读取/TLS 校验、HTTPX 传输、上游协议与用量验证。
  不导入 services/db/api；schemas/config 仍可作为既有契约与配置依赖。
- services/gateway.py：连接配置与价格的原子持久化、测试和调用业务入口。
- services/inference.py：保留文件，公开 receipt/validate_usage/settle_success_in_transaction
  供恢复复用；后者只使用调用者传入的游标，绝不自行提交。
- services/branding.py 与 services/admin_overview.py：从 platform.py 按实际职责分开。
- api/v1/platform.py：公开品牌；admin.py 保留管理员设置与总览。
- db/migrations.py：原 models.py；session.py 保留，因为本轮无需重命名事务设施。

## 兼容、安全、回滚

保留 HTTP 函数名、tags、路由参数和响应头，完整比较 OpenAPI。依赖注入、CSRF、
3 MB/256 KB 请求体限制及错误映射不变。SQL/事务/锁/回执顺序只搬移不改写。
旧实现不留一套重复维护；测试 mock 引用跟随真实实现移动，不删除行为断言。
不引入新依赖，不访问真实数据库或下载模型。当前运行进程不受测试启动影响。
回滚仅恢复本切片代码及导入，不操作迁移回滚或业务数据，保留此前工作区改动。
