## 背景与事实

- 当前后端已按 `api`、`schemas`、`services`、`core`、`db` 分层，不需要重建架构。
- `frontend/src/app.js` 有 709 行，包含请求、DOM、图表、筛选、页面初始化等职责。
- 管理员脚本通过经典脚本共享全局函数；简单移动文件会破坏初始化顺序。
- 后端 18 个测试文件平铺，包含纯逻辑、HTTP 契约、真实 MySQL 和容器端到端测试。
- 测试存在跨文件裸导入，以及通过 `parents[2]` 定位项目根目录的代码。
- 前端已有 npm 锁文件；Python 使用范围依赖，未配置统一项目元数据与 CI。

## 目标与范围

1. 保留模块化单体和现有后端分层，优先消除前端隐式全局依赖。
2. 为测试分类，保留默认回归入口与真实数据库/容器测试的显式 opt-in。
3. 提供轻量工程元数据和检查入口；不为目录整齐增加框架与生产依赖。
4. 同步构建、容器构建、规则和操作说明，防止文档与结构脱节。

## 非目标

- 不变更 URL、JSON、状态码、认证、CSRF、DOM ID、业务规则或计费事务。
- 不引入微服务、DDD、ORM、通用 Repository、Redis 或消息队列。
- 不改数据库结构，不执行迁移，不重启或部署现有服务。
- 不移动 `docs/` 下目录，不自动提交或推送。
- 本轮不重命名客服 CLI 和迁移执行模块；它们涉及既有脚本及导入兼容，单独处理。
- Python 锁文件和远程 CI 暂不实施：需要分别确定 external/local 两种依赖环境、CI 执行与维护策略，不能把本机环境冻结为跨平台锁文件。

## 验收

- 所有现有页面与管理员页面功能保持，浏览器没有模块加载错误或未定义函数。
- 构建产物包含完整相对导入目录，Docker 前端构建不依赖宿主缓存。
- 原默认 unittest 发现入口仍能运行；移动前后的测试用例数量不减少。
- 真实 MySQL/容器测试仍默认跳过，不意外读取真实凭据或访问服务。
- README 保持简短，中英文命令一致；详细结构和命令写入现有规则/知识文档。
- 未运行的验证明确标记未验证，不把构建成功等同于浏览器功能验证。
