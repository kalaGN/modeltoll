## 1. 本次确认的选型

原需求把数据库、密码策略、会话期限和账号来源列为待确认。2026-10-02 用户在本机
环境逐项授权以下选择，作为本阶段采用值，不是长期不可变契约：

| 事项 | 采用值 | 来源 |
| --- | --- | --- |
| 数据库 | 本机 MySQL 9.6.0，库 `laya_platform`，专用账号 `laya_app@127.0.0.1` | 用户选择 |
| 密码哈希 | Argon2id（`time_cost=3, memory_cost=64 MiB, parallelism=4, hash_len=32`） | 用户选择 |
| 账号来源 | 自助注册开放；管理员创建入口本次不做 | 用户选择 |
| 代码布局 | 按设计 §11 收敛到 `backend/app`，前端独立 `frontend/` | 用户选择 |
| 管理路由前缀 | `/v1/auth/*`，与设计 §14 提案一致 | 用户选择 |
| 前端样式 | Tailwind CSS 4.3.3 本地构建，无 CDN 运行时依赖 | 用户选择 |
| 会话 | 随机不透明 Token + 服务端 `user_sessions` 表，HttpOnly Cookie | 设计 §4 |
| 会话有效期 | 绝对 7 天（`Max-Age=604800`），无滑动续期 | 采用默认，待产品确认 |
| 登录限速 | 同账号+来源 15 分钟内 5 次失败锁定 15 分钟 | 采用默认，待产品确认 |
| 密码规则 | 8–128 字符，不做复杂度强制 | 采用默认，待产品确认 |

```bash
curl -s -c /tmp/j "$B/login" -o /dev/null
CSRF=$(grep laya_csrf /tmp/j | awk '{print $NF}')
curl -s -b /tmp/j -H "X-CSRF-Token: $CSRF" -H 'Content-Type: application/json' \
  -d '{"email":"t@example.com","password":"correct horse battery"}' $B/v1/auth/register
curl -s -b /tmp/j -c /tmp/j -H "X-CSRF-Token: $CSRF" -H 'Content-Type: application/json' \
  -d '{"email":"t@example.com","password":"correct horse battery"}' $B/v1/auth/login
curl -s -b /tmp/j $B/v1/auth/me
curl -s -b /tmp/j -H "X-CSRF-Token: $CSRF" -X POST $B/v1/auth/logout
```

| 其它失败/中断 | `not_billable`，`billing_reason` 记 `policy_succeeded_only` 或错误码 | 采用值 |

## 9. 用户复现清单的四个遗留缺陷（2026-10-03，服务运行于 `127.0.0.1:8030`）

### 9.1 缺陷与修复

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 模型没给出 `input_tokens` 时接口仍返回 200 | `inference.succeeded` 对缺用量走 `return failed(...)`，路由把返回值当成功响应 | 新增 `inference.UsageUnavailable`：先落 `failed` / `usage_unavailable` / `billing_status=pending`，再抛异常；`api/v1/inference.py` 的 `_settle` 捕获后对外返回 500 `{"code":"usage_unavailable",...}` |
