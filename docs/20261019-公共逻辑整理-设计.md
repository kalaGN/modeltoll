# 公共逻辑整理设计

依据：[需求](20261019-公共逻辑整理-需求.md)，用户直接确认前轮四项方案。

## 实现切片

1. api/errors.py 提供 error_content(code, message) 和
   http_error(status_code, code, message, headers=None)。参数显式传入，不反射读取任意异常，
   不注册 catch-all handler。现有领域适配函数保留类型约束，改用公共构造。
   JSONResponse 与 HTTPException 的差异保留；422、字符串 detail 与带额外字段的推理错误不改。
2. api/request_body.py 的 read_limited_body 接收 Request、字节上限和超限 detail，
   超限仍抛 413，逐块扩展前检查。不信任 Content-Length，不先无界读取。
   BoundedJsonRoute 保留原 route_class 和缓存完整 body 的时机；品牌路由仍先检查权限与 CSRF。
3. services/admin_management.py 的 _page/set_user_status/revoke_key 去除 code，
   业务字段和事务不动。api/v1/admin_management.py 的 _call 通过 success 添加 code。
   同步合成服务桩，不修改既有 HTTP 断言，不让服务导入 API 辅助函数。
4. api/responses.py 的 utc_range 复用 core/time.iso_utc。统计服务 parse_range 已归一
   为 naive UTC；不合并管理员与个人的跨度政策，不改变其他日期/游标字段。
   本机先对比 0001/0999/1000/2026 年格式，strftime 与 iso_utc 一致；补充 aware、
   微秒、None 的验证，保持原时钟字段和秒精度，core 的 None 行为不变。
