## 目录与职责

```text
backend/
  app/                   # 保持现有后端分层
  migrations/            # 保持现有 SQL 与回滚
  tests/
    unit/                # 纯逻辑、模拟数据库/外部调用的服务测试
    contract/            # TestClient HTTP 契约及构建/部署配置检查
    integration/         # 显式开启的真实 MySQL 测试
    e2e/                 # 显式开启的隔离 Compose 测试
    support/             # 跨测试模块确有复用的辅助对象
frontend/
  src/
    shared/              # HTTP、UI、工具与控制台公共能力，详见下文
    pages/               # 各页面入口及仅在相邻页面共享的业务逻辑
    styles/              # 从现有 input.css 按职责拆分的样式
    input.css            # 保留样式入口
  scripts/
    build.mjs            # 标准库递归复制源码并构建静态产物
  tests/                 # Node 内置测试，不新增测试依赖
pyproject.toml           # uv pip 默认使用项目 .venv，不重复维护依赖清单
.python-version          # 开发解释器系列 3.12
```

`contract` 单列是因为现有大量测试使用假数据库和 TestClient，称为真实集成或端到端不准确。
混合测试文件必要时拆为独立套件，不为分类而丢失用例或改变断言。

## 前端方案

- 使用浏览器原生 ES Modules，保留零运行时框架依赖。
- 公共模块显式 `export`，页面显式 `import`；不通过 `window` 共享业务函数。
- 每个 HTML 只加载自己的页面模块，公共控制台初始化由页面显式调用。
- 首先迁移 Key/统计页面，再迁移管理员脚本；登录内联逻辑最后迁移。
- 保留品牌逻辑和现有交互，明确初始化顺序，防止重复绑定事件或发出重复请求。
- 构建改为复制完整静态源码树，清理仅限已验证的 `frontend/dist` 生成产物；不清理源码或用户文件。
- Docker 的 COPY 与 `.dockerignore` 白名单同步允许新构建脚本；不扩大到凭据或缓存。
- 不做 UI 改版，不改变 Cookie 读取与 CSRF 发送规则。

浏览器自动化若采用额外工具或依赖，单独记录选型；此处不预设已经配置 Playwright 测试套件。

### 入口、依赖与初始化约定

- `api-keys.html` 仅加载 `<script type="module" src="/assets/pages/keys.js"></script>`；其余 HTML 同理映射至自己的入口。
- `/login` 与 `/register` 共用 login.js；`/admin/settings` 只加载 settings.js，由它调用 model-connection.js。
- 每个页面拥有自己状态和事件绑定，不导入其他页面入口。reports/filters.js 是无自动启动副作用的辅助模块。
- 依赖方向为：页面 → console/UI/HTTP/lib；console → HTTP/lib；UI → lib；HTTP 不依赖页面和 UI。lib 不发请求。
- 模块导入不自动绑定 DOM 或发请求；入口显式启动一次。branding 由入口调用，不保留第二个独立 DOMContentLoaded 监听器。
- 公共品牌读取是公开接口，不应误用会把 401 跳转到登录的已认证请求策略。保留独立非阻断错误处理。
- 控制台仍按现有行为先完成公共账号初始化、再执行页面业务初始化；不借重构修改错误处理与准入策略。
- `pages/login.js` 不加载控制台 shell；所有控制台页面仍有当前账号与退出能力。
- 不通过全局变量、函数名检测或 HTML 内联 onclick 建立依赖。

### 样式、构建与测试归属

- input.css 统一导入 Tailwind 与样式文件；迁移前记录原级联，处理跨段重复选择器，不能按文件名机械排序。
- Tailwind 的内容扫描必须覆盖 `src/pages/templetes/*.html` 与嵌套 JS；构建测试检查迁移前使用的关键类仍在 CSS 产物中。
- 构建明确将 `src/pages/templetes/*.html` 输出为 `dist/*.html`，保留文件名；JS 的 pages/shared 相对目录保持一致，CSS 输出为 `dist/app.css`。HTML 源码集中不改变后端 PAGES 映射和 `/assets` 挂载。
- 不把 HTML 在 dist 中重复输出到 pages/templetes；构建契约检查每个模板恰有一个根级产物，避免后端取错或 watch 留下旧页面。
- 构建只复制浏览器运行所需 HTML/JS 和实际静态资源；不复制测试、Node 脚本、node_modules、原始 CSS 或私有配置到 dist。先在随机临时目录完成构建，再替换固定 dist；拒绝以符号链接为 dist。
- watch 命令要同时考虑嵌套 JS/HTML 的复制与 CSS 更新，不能声称只运行 Tailwind watch 就能更新全部页面。
- `tests/unit` 测纯函数，不借 Node 测试模拟证明 DOM/焦点正确；DOM 和网络交互必须补浏览器验收。
- `tests/contract` 检查 HTML 入口唯一、模块导入全部可解析、无旧脚本混用、构建白名单和 dist 完整性。
- 测试 fixture 仅供验证，不随前端构建或 Docker 运行镜像发布。

### 实施粒度

先完成构建和公共基础，再逐页迁移；每迁移一个页面，替换其 HTML 入口并验证后再继续。
app.js/admin.js 可在过渡期服务尚未迁移的页面，但新旧入口不得在同一页面同时启动。
全部引用迁移后列出遗留文件清单，按项目规则确认删除，不保留空兼容脚本。
样式拆分放在 JS 页面迁移之后，单独比较外观，避免同时改变模块加载与 CSS 级联。

## 测试与工程配置

- 各测试目录加 `__init__.py`，保证标准库 unittest 递归发现。
- 提取已有跨文件复用的测试 Cursor 至 support，更新显式导入。
- 根目录定位集中到测试辅助模块，避免移动文件后 `parents[n]` 错位。
- 默认测试命令继续是 `PYTHONPATH=backend .venv/bin/python -m unittest discover -s backend/tests`。
- 新增分类命令；真实数据库和容器套件继续遵守原 opt-in 环境变量。
- 前端使用 `node --test` 覆盖构建产物、相对导入及公共纯函数；浏览器检查独立记录。
- `pyproject.toml` 不新增 formatter/Lint/类型检查工具，也不宣称既有门禁增加。
- 不把 `requirements-api.txt` 与 pyproject 同时作为两份手工生产依赖来源。
- 实施采用 `.python-version` 指定 Python 系列，pyproject 仅为 uv pip 工具配置；不引入打包构建后端、虚假项目依赖或空配置项。当前不支持以 uv sync 替代原安装流程。

示例风格：

```javascript
import { api } from "../shared/http/client.js";
import { initChrome } from "../shared/console/shell.js";

await initChrome();
await keysPage();
```

实际异常展示保持现有语义，不以示例替代既有行为。

## 风险、兼容与回滚

- 模块作用域及加载时机变化：逐页浏览器验证，不只依赖语法检查。
- 静态资源嵌套路径：验证源码导入与 dist 文件，以及容器构建白名单。
- unittest 发现遗漏/重名：迁移前后比较测试 ID 集合，而非只比较总数。
- 本轮不涉及数据库和模型并发变化；原单 worker、推理锁、计费边界保持。
- 回滚按前端/测试/配置三个切片恢复相应代码；不对用户工作区执行破坏性 Git 重置。
- 验证使用合成数据和隔离页面服务，不更改现有用户、Key 或在线服务。

## 边界

- 始终：保留用户修改、同步规则与文档、执行有证据的验证。
- 另行确认：生产依赖、锁定策略、CI、数据库、部署与额外重命名。
- 禁止：提交秘密或客户正文、自动提交/推送、以测试为由操作真实业务数据。
